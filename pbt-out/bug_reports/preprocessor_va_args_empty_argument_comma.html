Issue Synopsis

, ## __VA_ARGS__ deletes the comma for a supplied-but-empty variadic argument (gcc keeps it)

Expected behaviortokens [g ( a , )] — the comma survives a supplied-but-empty variadic argument (gcc 9.4 behavior)
Observed behaviortokens [g ( a )] — the comma is deleted as if the variadic arguments were absent
Impact assessmentWrapper/generated code calling variadic macros with an explicit empty last argument silently loses the comma and changes expansion arity (g(a, ) becomes g(a)); downstream C parses with the wrong argument count and no diagnostic.
Minimal counterexample#define VAC(fmt, ...) g(fmt, ## __VA_ARGS__) + VAC(a, ) -> SUT [g ( a )], gcc [g ( a , )]
