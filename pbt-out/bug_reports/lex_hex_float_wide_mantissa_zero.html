Issue Synopsis

Hex float literals wider than 64 bits silently evaluate to 0.0

Expected behaviorFloatLiteral(18446744073709551616.0)
Observed behaviorFloatLiteral(0.0)
Impact assessmentPrograms using large hex-float constants (e.g. exact 2^64) silently compile with 0.0 — silent wrong-code.
Minimal counterexamplelex 0x10000000000000000p0 → FloatLiteral(0.0), expected FloatLiteral(18446744073709551616.0)

Documentation: The cited documentation states this behavior IS handled; the code violates the document it ships with.

Author's text (verbatim): README:181 "Hex floats follow the C99 format 0x<int>.<frac>p<exp> and are converted via: value = (int_part + frac_part) * 2^exp"
