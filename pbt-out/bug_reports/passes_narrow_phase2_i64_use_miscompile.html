问题概述

narrow Phase 2 rewrites I64 bitwise ops to I32 without checking the use — I64 consumers get the zero-extended value (pipeline miscompile)

预期行为pipeline preserves the interpreted value: sext(a)|sext(b) = -1 for (1,-1)
实际行为Or rewritten to I32 with no re-extension; the I64 return reads 4294967295
影响评估run_passes(-O2, x86-64) compiles f(a,b){(i64)a | (i64)b} to return the zero-extended 32-bit Or: f(1,-1) = 4294967295 instead of -1
最小反例f(a:i32,b:i32)->i64 { Or(sext a, sext b) at I64 } narrowed to Or@I32 with no re-extension; f(1,-1)=4294967295 != -1 (pipeline-confirmed)

文档依据: 所引文档声明该行为已支持，代码违反了随代码一起发布的文档。

作者原文（逐字引用）: "narrows I64 bitwise operations (And, Or, Xor) to I32 when all operands are provably 32-bit values ... restricted to I32/U32 output to avoid sub-int register complications" — src/passes/README.md Integer Narrowing, Phase 2
