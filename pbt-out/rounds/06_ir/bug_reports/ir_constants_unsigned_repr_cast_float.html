high b1

Issue Synopsis

cast_float_to_target / cast_long_double_to_target store U8/U16 constants in sign-extending native variants, violating the documented zero-extension convention

Expected behaviorcast_float_to_target(200.0, U8).to_i64() == Some(200) (I64(200) per the from_i64 convention)
Observed behaviorIrConst::I8(-56), to_i64() == Some(-56)
Impact assessmentconstant folding / GVN / algebraic simplification read unsigned constants above the signed range (U8 > 127, U16 > 32767) as negative after any float->int constant cast — silent wrong folded values
Minimal counterexamplecast_float_to_target(200.0, IrType::U8) = I8(-56), to_i64() = -56 != 200 (also cast_long_double_to_target)

Documentation: The cited documentation states this behavior IS handled; the code violates the document it ships with.

Author's text (verbatim): "Store unsigned sub-64-bit types (U8, U16, U32) as I64 with zero-extended values to preserve unsigned semantics." — src/ir/constants.rs:437
