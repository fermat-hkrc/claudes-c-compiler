medium b3

Issue Synopsis

f64 subnormals misencoded by f64_to_f128_bytes and f64_to_x87_bytes (treated as normals of the source width)

Expected behaviordecode(f64_to_f128_bytes(5e-324)) == 5e-324 (normal f128 encoding of 2^-1074)
Observed behaviordecodes to 1.1125369292536e-308 (~2^-1023) — ~2^51 times too large
Impact assessmentsubnormal constants flowing into long-double data emission produce wrong bytes on ARM64/RISC-V (f128 emitted verbatim) and wrong x87 constants on x86
Minimal counterexamplef64_to_f128_bytes(5e-324) decodes to 1.1125369292536e-308 != 5e-324 (x87 twin equally wrong for subnormals)

Documentation: The cited documentation states this behavior IS handled; the code violates the document it ships with.

Author's text (verbatim): "Convert an f64 value to IEEE 754 binary128 (quad-precision) encoding (16 bytes, little-endian)." — src/ir/constants.rs:50
