- **Spec:** (none found) as a dedicated requirement/PR doc. Contract taken from assembler README.md:11 ("It accepts the same textual assembly that GCC's gas would consume"), encoder/mod.rs:3 ("Encodes AArch64 instructions into 32-bit machine code words"), encoder/mod.rs:997 `"sys" => encode_sys(raw_operands)` — raw operand string passed through unchanged. encode_sys rustdoc at system.rs:447: "Encode `sys #op1, Cn, Cm, #op2, Xt` instruction." ARM ARM SYS is `SYS #<op1>, <Cn>, <Cm>, #<op2>{, <Xt>}` with encoding 0xD5080000 | (op1<<16) | (CRn<<12) | (CRm<<8) | (op2<<5) | Rt; op1/op2 in [0,7], Cn/Cm in C0–C15, Xt a 64-bit GPR (XZR/LR accepted; Xt optional and defaults to XZR). Independent assembler reference: llvm-mc -triple=aarch64 -show-encoding (LLVM 15.0.6 at /home/toan/tools/llvm15-official/bin/llvm-mc). Cross-check: GNU gas (aarch64-linux-gnu-as) accepts the same valid form, rejects extra operands ("unexpected characters following instruction"), too few operands, op1/op2 out of [0,7] ("immediate value out of range 0 to 7"), CRn/CRm without the cN prefix or above 15, and W/SP/SIMD Xt ("operand mismatch" / "must be an integer register"). llvm-mc rejects the same extra/too-few/oob/wrong-class cases and also aliases SYS to DC/IC when the fields match; encodings still compare. Body comment system.rs:464 "xzr if no register specified" matches ARM optional-Xt. Body masks op1/CRn/CRm/op2 with &7/&0xF rather than declaring oob input out of domain.
